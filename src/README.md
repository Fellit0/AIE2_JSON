## Описание проекта

Парсер и анализатор JSON-логов LLM

## Требования и окружение

Python 3.0+
Используются только встроенные библиотеки
Дополнительная установка пакетов не требуется

## Инструкция по запуску

python parse_llm_logs.py

## Структура входных данных

Скрипт обрабатывает файлы в формате JSON Lines. Входной файл должен располагаться по пути `data/logs.json`. Каждая запись представляет собой JSON-объект, содержащий следующие поля:

 `timestamp` (string) — дата и время в ISO-формате (обязательное поле)
 `tokens_used` (integer) — количество затраченных токенов (опциональное)
 `latency_ms` (integer) — время ответа сервера в миллисекундах (опциональное)
 `prompt` (string) — текст запроса (опциональное)
 `response` (string) — текст ответа (опциональное)
 `error` (string) — код или текст ошибки при сбое запроса (опциональное)

## Обработка пропусков и ошибок

1. Критические ошибки синтаксиса (невалидный JSON или полностью пустой файл) прерывают выполнение программы с выводом диагностического сообщения в поток `sys.stderr` и кодом возврата 1.
2. Ошибки структуры данных (если строка файла не преобразуется в словарь) логируются в `sys.stderr`, после чего скрипт переходит к следующей записи.
3. Ошибки типов данных в ключевых полях (`tokens_used` или `latency_ms` содержат строку вместо числа) не вызывают падения программы. Скрипт записывает предупреждение в `sys.stderr` и безопасно пропускает данную запись при фильтрации и расчете метрик.
4. Отсутствие полей `latency_ms` или `tokens_used` обрабатывается корректно. Записи без токенов не участвуют в фильтрации, а записи без задержки игнорируются при расчете среднего времени и медианы, не приводя к ошибке деления на ноль. Если после фильтрации не осталось валидных записей времени, метрики задержки принимают нулевое значение.

## Обоснование инженерных решений

Отказоустойчивость: Скрипт защищен от пустых файлов и невалидных JSON. Ошибки логгируются в stderr и с кодом возврата 1

## Обоснование выбора дополнительной метрики и порога фильтрации

В качестве дополнительной метрики я выбрал медиану, так как она считает точнее, чем среднее арифметическое и устойчива к выбросам.
Медиана позволяет точнее оценить стабильность системы

Порог фильтрации зафиксирован на уроне 1000, помогая разделить запросы на легковесные и трудоемкие. Такой мониторинг важен для оптимизации затрат.
